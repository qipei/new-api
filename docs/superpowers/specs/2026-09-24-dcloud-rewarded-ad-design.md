# DCloud 激励广告奖励接入设计

日期：2026-09-24。状态：DCloud 路线已选择；本文件为待确认的实现设计，广告接口尚未上线。

## 目标与范围

为微信小程序提供可配置的激励广告奖励。后台控制卡片显示、单次奖励金额、每日奖励次数、领取间隔和奖励总预算。奖励发给观看者，进入现有收益钱包 `aff_quota`，并增加 `aff_history`；PC 与小程序共用收益明细，广告来源为 `rewarded_ad`。不改动原充值返佣接口，不改变手机号登录方式。

本仓库负责 Go 后端、PC 管理配置及收益明细、可交付的 uniCloud 回调桥接示例和接入文档。小程序源码不在当前仓库中；小程序组件与真实云资源的部署需要小程序项目及对应账号环境。

## 已选择的链路

小程序采用 uni-app 的 `<ad-rewarded-video>`，开启微信安全网络与 uni-open-bridge。uni-ad 配置回调到业务云函数 `token01AdRewardCallback`，由该函数验证事件后，通过 uni-cloud-s2s 的 HMAC-SHA256 请求本系统 Go 回调接口。用户系统和账务继续留在 Go 中。

选择业务云函数中转的原因：广告事件 ID 的签名与完整业务报文的认证是两个不同层次。只验证 `sha256(secret:trans_id)`，不能因此认定用户 ID、广告位和会话等其他字段也被签名保护。桥接函数先验证可信来源，再对完整的扁平报文认证，不允许把客户端任意请求包装成可信回调。

不采用原生微信小程序直接嵌入 uni-ad 组件的方式；DCloud 对该接入方式明确限制了服务端回调和安全网络能力。也不提供客户端自报 `isEnded` 即可发奖的降级模式。

## 身份和凭据

1. 用户继续通过已有手机号等方式登录，取得业务 access token。
2. 小程序调用 `uni.login()`，把一次性 code 交给新增的、必须登录的微信广告身份初始化接口。
3. Go 从微信换取 openid/session_key，将微信 AppID 与 openid 关联至当前业务账号。客户端不能指定收款用户 ID、openid 或 session_key。一个微信身份不能同时绑定多个业务账号领取奖励。
4. Go 将安全网络所需凭据通过认证的服务端通道同步给 uni-open-bridge；同步成功后只向小程序返回 openid 和可初始化标识。session_key、access_token、AppSecret 不下发、不写日志。
5. 微信凭据过期时重新初始化。微信 access_token 由统一缓存与锁管理，不在每次观看时重新获取。现有代码未有这一套小程序登录凭据桥接，须新增，不复用 Web 微信登录字段。

## 后台配置

新增独立的“激励广告”设置页面和 Root 管理接口，以一次事务保存完整配置，避免多个逐项保存请求产生半配置状态。

| 配置 | 规则 |
| --- | --- |
| 功能开关 | 默认关闭；开启前检查必需配置、单次额度与总预算大于零 |
| 单次奖励金额 | 按当前系统币种输入十进制金额字符串；服务端严格换算成整数额度并显示结果；TOKENS 模式直接填写整数额度 |
| 每用户每日奖励上限 | 正整数；初始建议 3 次，管理员可调整；这不是微信平台的观看次数上限 |
| 领取间隔 | 默认建议 60 秒，从上一笔成功奖励时间计算 |
| 全站每日奖励预算 | 按系统币种输入，换算并保存为额度；未设置正预算不允许启用 |
| uni-ad 广告位 | DCloud adpid，与微信广告位 ID 区分标注；首版只支持一个微信小程序广告位 |
| 微信小程序 AppID / AppSecret | 仅服务端使用；不复用腾讯 CAPTCHA 的 CaptchaAppId 或 AppSecretKey |
| uni-open-bridge 地址及认证配置 | 仅 HTTPS、固定管理员配置地址；不接收用户提供的回调或桥接地址 |
| DCloud 广告回调密钥、S2S 密钥 | 分开配置，至少 32 字节随机 S2S 密钥；不向普通用户和通用配置列表返回明文 |

后台修改奖励金额仅影响之后创建的观看会话。已经开始的观看按创建时快照结算。关闭开关停止新会话，已有有效会话仍可完成入账；因此关闭不是撤销已承诺奖励的操作。更新广告位或密钥前先停用并等待未结束会话清零，避免旧回调失去验证依据。

## 接口边界

以下是本系统设计的路径，不是 DCloud 原生接口；均为新增接口，现有 `/api/status` 只追加公开布尔字段。

| 接口 | 作用 |
| --- | --- |
| `GET /api/status` | 新增 `data.rewarded_ad_enabled`，仅配置完整且启用时为 true |
| `GET/PUT /api/option/rewarded-ad` | Root 获取／保存广告配置；GET 返回密钥是否已配置，不返回密钥；空密钥表示保留原值 |
| `POST /api/user/self/rewarded-ad/wechat-session` | 登录后提交微信 code，初始化或刷新安全网络身份 |
| `GET /api/user/self/rewarded-ad` | 返回奖励、币种、今日成功次数／预约次数／剩余名额、冷却时间、未完成会话和不可领取原因 |
| `POST /api/user/self/rewarded-ad/sessions` | 登录后申请观看会话，客户端提交幂等 request_id，不提交奖励金额；返回 session_id、adpid、urlCallback 所需参数和有效期 |
| `GET /api/user/self/rewarded-ad/sessions/:id` | 仅查询本人会话；返回 pending、credited、expired 或 review_required，以及已到账时的金额 |
| `POST /api/rewarded-ad/dcloud/callback` | 仅接受经过 S2S 认证的业务云函数回调，不接受用户 access token 替代认证 |
| `GET /api/user/self/referral/rewards` | 原统一明细扩展 `rewarded_ad` 来源，结构保持兼容；PC 与小程序都使用它 |

观看状态和成功奖励返回现有 `{quota, amount}` 与 `currency` 对象，不要求客户端再次换算。业务错误提供稳定 code，例如 disabled、identity_required、daily_limit、cooldown、budget_exhausted、session_expired；未登录为 401，越权会话返回 404。

## 观看与回调协议

小程序先准备广告并等待加载成功，再申请会话和展示；在创建／预加载的组件会捕获 urlCallback 时，必须按会话重新创建组件并验证透传参数，不能让下一条广告沿用上一条会话。具体组件实例生命周期需真机联调确认。

- Go 生成至少 128 位随机不可猜测 session_id，保存用户、微信身份、广告位、奖励额度、创建日期（Asia/Shanghai）与过期时间。
- `urlCallback.userId` 使用 Go 返回的标识，`extra` 只携带 Go 生成的会话标识，不承载奖励金额。不得相信客户端自己拼接的目标账户。
- 桥接云函数不开放 URL 化的匿名转发入口；只接受云端函数来源，验证 adpid、platform=`weixin-mp`、事件签名及必要字段。拒绝 client/http/server 来源。生产环境必须不存在把任意客户端 event 原样转交该函数的其他云函数。
- 桥接函数通过 uni-cloud-s2s 的 HMAC-SHA256 对扁平字段签名：版本、adpid、platform、provider、trans_id、user_id、extra、原始事件签名。Go 只允许该算法并验证时间戳（默认容差 300 秒），恒定时间比较签名；拒绝嵌套对象、重复参数、未知签名算法和超长请求。
- Go 同时验证广告事件签名、会话用户与 user_id 的对应关系、广告位、有效期及账户状态；奖励只读会话快照。签名通过不等于允许改写收款人。
- 以提供方 + 广告位 + trans_id 形成持久化唯一事件；相同事件及相同载荷重复到达返回已处理结果。相同事件携带冲突载荷时拒绝并审计，不能重新定位至另一个账号。
- Go 提交成功后，桥接函数向 DCloud 返回 `isValid: true`。数据库故障、网络超时或验证失败不得返回成功掩盖错误；网络故障按同一事件重新请求。
- 桥接端保存已验证但未送达的事件，使用持久重试队列；重复投递使用同一个 trans_id，S2S 请求时间戳可以重签。不得仅依赖一次函数调用内的重试。

uniCloud 来源限制和 S2S 并不能替代 DCloud 的微信安全网络配置。真实广告到达、身份对应关系和参数透传必须在正式启用前验证；不宣称接上一个 HTTP 回调就能杜绝所有作弊或保证广告平台最终结算。

## 账务、限额与延迟处理

新增会话、已验证广告事件、每日预约计数三类数据，复用现有 ReferralRewardRecord；均保存在主库，因为需要与收益钱包保持同一事务。

会话申请事务中锁定相应计数，原子预约当日用户名额与全站预算。每个账号同时最多一个待确认会话，重复 request_id 返回原会话。显示的剩余名额要扣除预约，不能把它描述为保证能拉取到的广告数量。

首版会话有效期 15 分钟，以服务端时间为准。15 分钟内的可信回调可自动入账；过期释放预约，不计成功次数。超过有效期的真实回调入库标记 review_required，保留证据用于核验，不自动突破限额或丢弃记录。页面展示“奖励待核验”，不能再次按同一广告申请奖励。有效期是业务接入策略，不是 DCloud 官方承诺的回调时间。

自动发奖事务执行：事件去重 → 会话验证 → 预约转为已使用 → 新增来源为 rewarded_ad 的收益记录 → 增加 aff_quota 与 aff_history → 会话标为 credited。所有步骤必须一起提交或一起回滚，钱包加法受 common.MaxWalletQuota 保护。Redis 只作前置限流，不能作为唯一发奖记录。

按原会话日期结算，跨零点不把同一会话算两次。读取和申请新会话时懒清理过期预约，并有定时补偿任务；多实例清理依靠数据库条件更新保证只释放一次。广告事件去重记录与收益记录保留，不能因清理会话而允许旧事件重领；仅短期诊断日志可按策略清理。

## PC 与小程序展示

- PC 钱包明细改用统一收益接口，并显示广告奖励、邀请注册奖励和充值返佣，不再仅展示充值来源。余额、累计收益沿用当前卡片字段，金额符号跟随后台。
- 小程序状态开关为 false、缺失或请求失败时隐藏广告卡片；不创建广告对象。
- 无广告和网络失败给出明确提示，不扣成功奖励次数、不无限重试；1004 不能翻译成“今日次数已用完”。
- 完整观看后的客户端回调只触发查询，显示“奖励确认中”；查询按 2/4/8/15 秒退避，最多持续 60 秒，随后允许用户稍后查看原会话。
- 查询超时不判定发奖失败、不创建替代会话；恢复页面后查询原会话。到账后显示“奖励已存入收益账户”，刷新收益金额和明细，不提示模型可用余额已增加。

## 交付和验证

1. 后端配置、公开开关、微信凭据初始化、观看状态与会话、可信回调及账务事务。
2. PC 广告设置与统一收益明细，七种语言文案；原接口兼容。
3. uniCloud 桥接和持久重试参考实现、部署配置说明、小程序调用示例；不得包含真实密钥。
4. 小程序接口文档补完整字段、错误码、流程、广告加载失败与待确认状态；上线前继续标记未实现部分。
5. Go 测试覆盖假签名、金额伪造、串改收款人、重复和并发回调、超限、跨日、过期、关闭开关后的在途结算、事务失败回滚以及钱包溢出。SQLite/MySQL/PostgreSQL 的迁移与事务语义均需验证。
6. 前端测试配置保存失败不启用、密钥不回显、金额换算、三种收益来源；运行类型检查、lint、构建。
7. 真机完成一笔真实广告并核对两端金额与唯一记录；重复回调不增余额，模拟后端短时不可用能恢复投递。云函数与公网 HTTPS 回调未联调前默认保持关闭。

## 外部配置材料

需要微信小程序 AppID、uni-app 项目、uni-ad 微信广告位、已开通安全网络的 uniCloud 服务空间、uni-open-bridge 配置，以及公网 HTTPS 服务地址。敏感密钥填写到后台或云端配置，不发送到聊天、不写入接入文档。localhost 和 192.168.x.x 地址不能直接作为 uniCloud 的业务回调目标。
