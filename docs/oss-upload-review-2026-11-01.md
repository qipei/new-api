# 图片上传与首页通知验证记录

日期：2026-11-01。范围：本地测试服务 `http://localhost:3000`，使用已配置的真实 OSS。没有调用付费模型接口。

## 首页通知

- 首页打开或刷新时，成功获取到未读的系统通知后弹窗显示；游客及已登录用户均适用。
- 关闭后，同一浏览器刷新不重复显示相同内容；通知更新后重新提示。通知铃铛仍支持手动查看。
- 获取失败时不弹旧缓存通知；空通知不弹出；其他页面不自动弹出。
- 关闭按钮采用登录页的黄色背景、深色文字、14px 圆角、46px 高度和悬停颜色。
- 前端相关五个测试文件共 40 项通过，类型检查及 lint 通过；按钮样式调整后另行重跑 16 项通知测试、类型检查、lint 与格式检查。

## 真实 10 并发上传

当前配置：每实例最多 10 个活动上传，每用户每分钟 10 次，单文件最大 20 MiB。

同时建立 10 条上传连接，每条发送有效 PNG 文件的一部分并保持连接，确认同时存在 10 个活动临时文件后，再全部继续上传至 OSS。

| 项目 | 结果 |
| --- | --- |
| 文件数量 | 10 |
| 单文件大小 | 4,721,114 字节，约 4.50 MiB |
| 总大小 | 47,211,140 字节，约 45.02 MiB |
| 上传结果 | 10 条均 HTTP 200 |
| 请求耗时 | 4.967–10.190 秒，包含人为保持接收阶段 |
| 下载验证 | 10 条链接均可读取；其中 1 个文件完整下载 SHA-256 一致 |
| 请求结束后临时文件 | 0 |
| 容器内存采样 | 基线 25.82 MiB，最高采样 37.62 MiB |
| 容器 CPU 采样 | 最高采样 1.21% |
| OSS 传输期间 `/v1/models` | 全部成功，采样 4.58–22.85 ms |

资源数值是本地容器的离散采样，不代表瞬时峰值，也不能代替生产服务器带宽及模型流式请求压测。

并发上限与用户请求频率是两个独立限制。同一用户第 11 次请求可能先触发每分钟限制，因此实例第 11 条活动请求返回 429 的行为由隔离测试单独验证；也覆盖降低上限不中断活动请求、释放后恢复接收的行为。

## 审查发现与修复

1. 上传原先可能忽略第一个文件后的额外文件或参数。现在只允许单个 `file`，额外内容在写入 OSS 前拒绝。
2. HTTP/1 错误响应可能因服务器继续读取未完成请求体而延迟。现在及时关闭错误请求；合法 multipart 后也会在接收期限和并发槽位内读完 HTTP 请求体，再上传 OSS。
3. multipart 默认头部解析预算过大。现在将头部读取限制为 64 KiB，同时保留大文件流式处理，避免头部造成额外内存占用。
4. 保存存储配置时数据库失败可能误报成功。现在使用能够返回持久化错误的批量选项保存路径；失败时不更新内存配置。
5. 缩短临时文件清理间隔可能仍等待原来的长间隔。现在每分钟根据当前配置重新判断到期时间；不删除正在使用的临时文件。

新增回归覆盖实际 TCP 未完成请求、HTTP 请求体结束前不写 OSS、超大 multipart 头、额外字段/文件、超过 1 MiB 的合法 PNG、并发准入及释放、数据库保存失败、清理周期缩短等路径。

后端相关测试、`go vet` 和根模块 `go build ./...` 通过；另行运行 controller/service 完整测试通过。代码已更新到本地服务，尚未提交。
